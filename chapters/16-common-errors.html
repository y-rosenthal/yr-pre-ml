Common errors and how to fix them#

Everyone who writes code sees error messages, every day. An error message is not a sign that you are bad at programming: it is Python telling you, as precisely as it can, what it could not do. This appendix collects the errors that you are most likely to meet in this book. For each one, we show what you see, what the message means, and how to fix it. You do not need to read it in order: jump to the error that you have.

In this appendix, you will learn to:

  • read an error message, starting from its last line;

  • recognize the most common errors of Python, NumPy, pandas and scikit-learn;

  • fix each of them, and know what to check first when you are stuck.

import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression

DATA_URL = "https://raw.githubusercontent.com/y-rosenthal/yr-pre-ml/main/data/"

How to read an error message#

When Python cannot run a line, it stops and shows an error message. A long message is called a traceback: it lists the lines that Python was running when the problem happened, from your line down into the code of pandas or scikit-learn. Most of it is meant for experts. Two parts matter:

  • The last line. It has the form ErrorType: message. The type names the kind of problem (NameError, KeyError, ValueError, …), and the message gives the details.

  • Your line. In Colab, an arrow (---->) points at the line of your cell that failed. In Thonny, look for the line of the message that names your file.

Each section below shows an error on purpose, explains its last line, and then shows the fix. The website shows the messages of Colab’s versions of Python and the packages. Other versions may word a message a little differently, but the kind of error is the same.

Note: an error does no harm. Fix the cell and run it again. In Colab, Runtime > Run all stops at the first cell with an error, so fix that cell first.

NameError: a cell that did not run#

Suppose that we open this notebook and run a cell in the middle, without running the cells above it:

sales.head()

---------------------------------------------------------------------------
NameError                                 Traceback (most recent call last)
Cell In[2], line 1
----> 1 sales.head()

NameError: name 'sales' is not defined

The last line is NameError: name 'sales' is not defined. A name is the name of a variable or a function. Python knows only the names that the code it already ran has created. No cell has created sales yet: the cell that reads the file did not run.

This happens a lot in notebooks. When you open a notebook again, or when Colab restarts after some time without use, every variable is gone, even though the cells may still show their old outputs.

The fix: run the cell that creates the name, and the cells above it. In Colab, Runtime > Run before runs every cell above the current one. Here, we read the file:

sales = pd.read_csv(DATA_URL + "sales.csv")
sales.head()
date store region category units price discount
0 2025-01-01 S1 North Clothing 3 46.99 0.1
1 2025-01-01 S8 West Grocery 9 2.99 0.0
2 2025-01-01 S2 North Grocery 11 5.99 0.0
3 2025-01-01 S8 West Grocery 9 11.99 0.0
4 2025-01-01 S5 East Grocery 13 3.99 0.2

Now sales exists, and head() shows the first five sales.

NameError: a typo in a name#

The same error appears when we misspell a name. Here we wrote sale instead of sales:

sale["units"].sum()

---------------------------------------------------------------------------
NameError                                 Traceback (most recent call last)
Cell In[4], line 1
----> 1 sale["units"].sum()

NameError: name 'sale' is not defined

The last line is NameError: name 'sale' is not defined. Python does not guess what we meant: sale and sales are two different names, and so are Sales and sales (names are case-sensitive). When Python runs a script, for example in Thonny, it may add a hint to the message: Did you mean: 'sales'?.

The fix: correct the spelling.

sales["units"].sum()

np.int64(8949)

The stores sold 8,949 units in all.

ModuleNotFoundError: a misspelled package#

Here we mistype the name of the package in an import line:

import pandsa

---------------------------------------------------------------------------
ModuleNotFoundError                       Traceback (most recent call last)
Cell In[6], line 1
----> 1 import pandsa

ModuleNotFoundError: No module named 'pandsa'

The last line is ModuleNotFoundError: No module named 'pandsa'. A module is a package, or a part of one, that import loads. Python looked for a package named pandsa and found none. (In Colab, a note under the message may suggest installing the package. Here nothing needs to be installed: the name is misspelled.)

This error has two usual causes:

  • a typo in the name, as here;

  • a package that is not installed. Colab has every package of this book, but in Thonny you install each one once, with Tools > Manage packages… (the chapter Colab, Thonny and other IDEs shows how). Remember that scikit-learn is installed as scikit-learn but imported as sklearn.

The fix for a typo: correct the name.

import pandas as pd
pd.__version__

'2.2.3'

This time the import works, and pd.__version__ shows the version of pandas.

SyntaxError and IndentationError: code that is not Python#

Some errors appear before any line runs. Python first reads the whole cell. If the code breaks the rules of the language, Python stops at once with a SyntaxError, and no line of the cell runs. (We show these errors as text, not as cells that run.)

A for line without the colon at its end:

for price in [4.99, 12.50, 3.25]
    print(price)

    for price in [4.99, 12.50, 3.25]
                                    ^
SyntaxError: expected ':'

A missing closing parenthesis:

print(sales.head()

SyntaxError: incomplete input

That is what Colab says: the cell ended while a ( was still open. In Thonny, Python says it more clearly: SyntaxError: '(' was never closed.

A line that should be indented, but is not:

for price in [4.99, 12.50, 3.25]:
print(price)

IndentationError: expected an indented block after 'for' statement on line 1

The caret ^ (or ^^^^^) marks the place where Python noticed the problem. The mistake is there or just before it, sometimes at the end of the line above.

The fix: add the missing :, ) or quote, or indent the lines of the block (four spaces).

TypeError: adding text and a number#

We want to show a total with a label:

revenue = 1234.5
"Revenue: $" + revenue

---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[8], line 2
      1 revenue = 1234.5
----> 2 "Revenue: $" + revenue

TypeError: can only concatenate str (not "float") to str

The last line is TypeError: can only concatenate str (not "float") to str. A type is the kind of a value: str (text), int (a whole number), float (a number with a decimal point). + joins two strings (it concatenates them), or adds two numbers, but it cannot do both at once. Python does not guess whether we want text or a number.

The fix: turn the number into text with str(), or, better, use an f-string:

print("Revenue: $" + str(revenue))
print(f"Revenue: ${revenue:,.2f}")

Revenue: $1234.5
Revenue: $1,234.50

Both lines work. In the f-string, :,.2f shows the number with a comma between the thousands and two decimals: $1,234.50.

Note: the other order, 100 + "5", gives a different message for the same problem: TypeError: unsupported operand type(s) for +: 'int' and 'str'.

HTTPError: HTTP Error 404: Not Found

The message is long, because it goes deep into the code that reads from the internet. The last line is HTTPError: HTTP Error 404: Not Found. HTTP is the language of the web, and 404 is the web’s code for “there is no page or file at this address”. Python reached GitHub, but GitHub has no file with that name. (In Thonny, the type is written in full: urllib.error.HTTPError.)

The fix: check the file name against the list in the appendix The datasets. File names are case-sensitive: Customers.csv is wrong too.

customers = pd.read_csv(DATA_URL + "customers.csv")
customers.shape

(500, 6)

The file is found: 500 rows and 6 columns.

Note: an error that mentions URLError, SSL or CERTIFICATE is a different problem: Python could not reach the website at all. Check that you are online, or use a copy of the file on your computer (next section).

FileNotFoundError: a file on your computer#

In Thonny, you may read a copy of a data file that you saved on your computer (the chapter Colab, Thonny and other IDEs shows how):

customers = pd.read_csv("customers.csv")

When Python cannot find the file, the last line is:

FileNotFoundError: [Errno 2] No such file or directory: 'customers.csv'

A file name without a folder, such as "customers.csv", means “the file of this name in the current folder”. In Thonny, that is the folder of your script. So check three things:

  1. The file is in the same folder as your script, and you have saved the script (an unsaved script has no folder).

  2. The name is exactly right. Some browsers save the file as customers.csv.txt or customers (1).csv: rename it.

  3. You are not in Colab. Colab runs on Google’s computers, so it cannot see a file on yours. In Colab, read the file with DATA_URL + "customers.csv".

ValueError: arrays of different lengths#

We have four sales: the units of each sale, and the price of one unit. But one price is missing:

units = np.array([3, 1, 4, 2])
prices = np.array([2.50, 10.00, 4.00])
units * prices

---------------------------------------------------------------------------
ValueError                                Traceback (most recent call last)
Cell In[14], line 3
      1 units = np.array([3, 1, 4, 2])
      2 prices = np.array([2.50, 10.00, 4.00])
----> 3 units * prices

ValueError: operands could not be broadcast together with shapes (4,) (3,)

The last line is ValueError: operands could not be broadcast together with shapes (4,) (3,). The operands are the two arrays that * works on. Broadcasting is NumPy’s word for matching up the values of two arrays so that it can compute element by element. The shape (4,) means a 1-D array of 4 values, and (3,) one of 3 values. NumPy cannot pair 4 units with 3 prices.

A ValueError means that a value has the right type but a wrong value: here, two arrays, but of lengths that do not fit together.

The fix: find the missing value, so that both arrays have one value for each sale. .shape (or len()) shows the lengths:

prices = np.array([2.50, 10.00, 4.00, 7.50])
print(units.shape, prices.shape)
units * prices

(4,) (4,)

array([ 7.5, 10. , 16. , 15. ])

Both arrays have 4 values now, and we get the revenue of each sale.

The last line is ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all(). (pandas 3 leaves a.bool() out of the list.) Python’s and needs a single True or False on each side. big_north = sales[(sales["units"] > 10) & (sales["region"] == "North")]
len(big_north)

27

27 sales match both conditions. or and not give the same error: use | and ~ instead.

Common mistake: forgetting the parentheses, as in sales["units"] > 10 & sales["region"] == "North". Python computes & before > and ==, so this means something else, and it stops with a TypeError whose message is hard to understand. Always put each condition in parentheses.

A warning: chained assignment#

Not every problem stops the code. A warning is a message that Python shows while the code goes on. Here we copy sales, and try to set the discount of store S1 to 0.5:

sales2 = sales.copy()
sales2[sales2["store"] == "S1"]["discount"] = 0.5

(We show this code as text, because its warning differs between pandas 2 and pandas 3.) In Colab (pandas 2), the warning says:

SettingWithCopyWarning:
A value is trying to be set on a copy of a slice from a DataFrame.
Try using .loc[row_indexer,col_indexer] = value instead

In pandas 3, it starts like this (despite its name, it is a warning too):

ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment.

In both versions, sales2 does not change. The line has two steps in a chain: sales2[sales2["store"] == "S1"] makes a new, temporary table with the rows of S1, and ["discount"] = 0.5 changes that temporary table, which is then thrown away.

The fix: do it in one step, with loc (the chapter Filtering rows):

sales2 = sales.copy()
sales2.loc[sales2["store"] == "S1", "discount"] = 0.5
sales2.loc[sales2["store"] == "S1", "discount"].unique()

array([0.5])

The only discount left in the rows of S1 is 0.5: the change worked, with no warning.

When you are stuck#

  1. Read the last line: the type of the error and its message.

  2. Find your line: the arrow in Colab, or the line with your file name in Thonny.

  3. Check the names: the spelling and the capitals of variables, columns (df.columns) and files.

  4. Check what you really have: type(x), x.shape, df.dtypes and df.isna().sum() show it.

  5. Run the notebook from the top with Runtime > Restart session and run all. Cells that ran out of order can leave variables that the code above them does not explain. A restart clears them; Run all alone does not.

  6. Search the web for the last line (without your own variable names), or ask someone. Show them the whole message, and the code that gave it.

Summary#

  • Read the last line of an error message first: ErrorType: message.

  • NameError: no code created that name. Run the cells above, or correct the spelling.

  • ModuleNotFoundError: a misspelled package name, or a package that is not installed.

  • SyntaxError and IndentationError: the code is not valid Python, and no line of the cell runs.

  • TypeError with +: text and a number. Use an f-string, f"Revenue: ${revenue}".

  • HTTPError: HTTP Error 404: Not Found: a misspelled data file name. FileNotFoundError: a file on your computer that is not in the script’s folder.

  • KeyError: a misspelled column name. Check df.columns.

  • ValueError: operands could not be broadcast together: arrays of different lengths.

  • ValueError: The truth value of a Series is ambiguous: and, or, not instead of &, |, ~.

  • SettingWithCopyWarning (pandas 2) or ChainedAssignmentError (pandas 3): chained assignment, which may not change the table (in pandas 3, it never does). Use df.loc[mask, "col"] = value.

  • fit errors: could not convert string to float (use pd.get_dummies) and Input X contains NaN (use dropna or fillna, on the table before you take X and y).

Question 9 (Challenge)#
